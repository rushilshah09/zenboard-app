### ScrollArea nested-scrollbar root-cause fix (2026-07-20, DS-level, verified)
Bug: project tab bar showed BOTH a horizontal scrollbar under the tabs AND a vertical one beside them (nested-scroll feedback loop). Root cause was NOT the tabs — it was `components/ds/ui/scroll-area.tsx` setting only ONE axis to `overflow: auto`. Per CSS spec, when one axis is `auto` and the other is left `visible`, the browser COERCES the visible axis to `auto` too → spurious scrollbars whenever content sub-pixel-overflows the cross axis (the Tabs' absolute underline at `-bottom-px` triggered a 1px vertical overflow → vertical bar → stole width → `min-w-full` list overflowed x → horizontal bar). This latently affected EVERY ScrollArea in the app.
Fixes: (1) ScrollArea now pins the cross-axis: `axis==='x' → overflow-x-auto overflow-y-hidden`, `axis==='y' → overflow-y-auto overflow-x-hidden` (hidden+auto never coerces). (2) Added `hideScrollbar` prop + `.zb-no-scrollbar` utility in globals.css (scrollbar-width:none + ::-webkit-scrollbar hidden) — used by Tabs so the horizontal tab-scroll pattern shows NO bar, only the fade mask. (3) Tabs underline `-bottom-px`→`bottom-0` so overflow-y:hidden can't clip it. (4) projects-workspace: tab row de-nested (was flex+spacer+inline SegmentedControl → plain full-width `<Tabs>`; the List/Board/Calendar switcher moved INTO the Tasks panel, right-aligned); property strip gap `mb-7`→`mb-5`; rail + detail scroll containers got explicit `overflow-x-hidden` (same coercion class of bug).
